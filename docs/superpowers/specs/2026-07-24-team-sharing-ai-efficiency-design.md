# 小组分享：工作节奏、AI 提效与个人成长设计说明

## 目标

制作一个适合小组现场分享及会后阅读的单页 HTML。页面采用左侧固定导航、中间主体内容的结构，以轻松但专业的语气说明团队考勤原则、OpenClaw Hub 带来的测试提效能力，以及测试人员的个人发展方向。

## 内容结构

1. **开场**：用“把时间用在更有价值的事情上”建立分享主题。
2. **工作制度**：强调每日有效工作时间满足 8 小时、正常情况下 10:00 前到岗、临时有事及时请假、前一晚 23:00 后结束工作时次日可合理弹性。
3. **AI 提效**：围绕需求分析、代码分析、用例编写、Bug 创建与分析、风险报告整理、测试工具开发、知识总结分享七类场景说明 AI 能协助测试提效什么；不介绍 Hub 系统本身。先说明 Agent 相比人和固定脚本具有概率性波动，Skill 只能降低方差而不能保证确定结果，再补充大模型与 Agent 的形象定义、常用 Agent/编程工具定位，以及工具与模型组合的个人使用体感。用 Skill #210、用例库 #26 与 #29 的真实同模块数据展示 AI 用例从检查点式写法升级为可执行、可追溯的结构化方案。
4. **个人发展**：业务理解、专业测试技术、研发质量风险判断和团队管理是核心能力，AI 是能力放大器而不是替代品；通过“成长区/基本盘/风险区”三层定位图，引导成员判断当前状态，并从稳定完成任务走向承担挑战和持续学习。
5. **行动建议**：给出可在一周内执行的小实践，鼓励多尝试、复盘和沉淀。

## 视觉与交互

- 风格：轻松专业的内部分享手册，使用暖白纸张色、深蓝墨色和橙色强调色。
- 布局：桌面端左侧固定导航、右侧连续滚动内容；窄屏下导航变成顶部横向滚动条。
- 图形：全部使用内嵌 SVG、CSS 图形和 Hub 流程示意，不依赖网络图片。
- 交互：导航平滑滚动、当前章节高亮、滚动进入动画、阅读进度条和返回顶部按钮。
- 可访问性：语义化章节、清晰焦点样式、尊重 `prefers-reduced-motion`。

## 内容边界

- 考勤内容仅依据用户提供的四项原则，不补充未确认的处罚、审批或例外规则。
- 不将 AI 描述为替代测试人员；所有 AI 场景强调人工判断、复核和责任闭环。
- Hub 能力以当前系统已有的需求、工程、用例、任务、Workflow 和知识沉淀能力为依据。
- 工具和模型比较必须标注为个人使用体感，不写成统一性能榜单；第三方代充需提示账号来源、支付合规、封号和稳定性风险。
- 用例案例只比较两个库中同一个“3C 车辆被动技能通用规则”模块；结论突出格式合规、操作可执行性和异常覆盖，不用总库数量制造误导。
- 库级指标之后增加一组真实用例明细：库 #26 的 TC_1893 与库 #29 的 TC_034 围绕“同一事件不能重复消费”这一共同风险主题，对比前提、操作、预期和观测证据；明确它们是覆盖升级案例，不描述成同一条用例的一对一改写。
- 覆盖度不能只用“39 → 41”说明。展示新版的三类证据来源：需求分析保留原 39 条覆盖意图，Hub 游戏入口全景补齐车库、模式、关卡与局内事件路径，Skill 经验补充异常、持久化、隔离和状态边界；列出 TC_013、TC_015～TC_029 的重点重构主题。
- 不把 Skill 描述为稳定性保证；明确同样输入可能产生不同路径和输出，需要持续观察过程、人工复核并根据偏差优化 Skill。给 Agent 的输入按“底线、基本、核心规则”排序，保持言简意赅。
