# OpenClaw Hub 项目最新进展

> 更新时间：2026-05-04  
> 范围：OpenClaw Hub、Hermes Agent 代建部署、TAPD 集成、测试计划/测试任务、SSE 通信稳定性

## 一、总体状态

OpenClaw Hub 已从基础的 Agent/Skill/知识管理，推进到支持测试经理工作流的综合平台。当前重点能力包括：

- Hub 统一管理 OpenClaw 实例、Skills、规则、知识、测试计划、测试任务、用例执行和通信中心。
- Hub 可代建 Hermes Agent，并通过 systemd 隔离运行，支持大模型、企微 Bot、sidecar v2 通信和额外工作目录配置。
- TAPD 集成 Skill #113 已重整为通过 Hub API 代查 TAPD，避免 OpenClaw 直接持有 TAPD 凭证。
- 测试计划模块已支持下拉选择计划、Agent 写入测试报告、用例执行分页、按 owner 分配和展示测试任务。
- 多轮线上 500/连接池耗尽/SSE 死锁问题已完成关键修复，服务目前可正常访问。

## 二、已上线能力

### 1. Hermes Agent 代建与运行隔离

Hub 代建 Hermes Agent 当前统一使用 systemd，不再开放 Docker 入口。

已完成：

- 默认部署目标机与 Hub 分离：Hub 在 `clawteam.woa.com:18800`，Hermes Agent 目标机为 `9.134.51.249:36000`。
- 每个 Agent 使用独立 systemd 用户：`oclaw_<id>`。
- 私有数据目录固定在 `/opt/openclaw-agents/claw-<id>-<safe>/data`。
- 共享目录固定为 `/opt/agent_share`。
- systemd unit 使用 `ProtectSystem=strict`、`NoNewPrivileges=true`、`ReadWritePaths=<agent_data> /opt/agent_share`。
- Hermes Gateway 与 sidecar v2 均由 Hub 部署、配置和重启。
- 大模型设置保存后会同步远端 `config.yaml/.env/wrapper/unit`，再重启 gateway 和 sidecar。
- 企微 Bot 绑定支持保存 Bot ID/Secret，Secret 不回显，运行环境写入 `WECOM_*` 变量。

### 2. Hermes Agent 工作目录设置

OpenClaw 卡片设置已新增“工作目录”页签。

已完成：

- `openclaw_instances.work_dirs` 保存额外工作目录列表。
- 页面支持每行填写一个绝对路径。
- 保存后会同步到 systemd `ReadWritePaths`，并写入 `AGENT_WORK_DIRS` 环境变量。
- 部署/重启时会创建目录并设置权限：`chown <oclaw_id>:openclaw_agents`、`chmod 2770`。
- 已禁止配置系统目录及其子目录，例如 `/root/*`、`/etc/*`、`/usr/*`、`/opt/openclaw-web/*`。

注意：

- `/root/racinggo` 这类路径即使写入 `ReadWritePaths` 也无法被 `oclaw_14` 正常访问，因为 `/root` 父目录本身不可穿越，且 gateway unit 启用了 `ProtectHome=true`。
- RacingGO 这类工程目录应迁移到 `/opt/agent_work/racinggo` 或 `/opt/agent_share/racinggo` 后再授权。

## 三、线上稳定性修复

### 1. SSE 连接池耗尽

问题：

- SSE 长连接里频繁 ORM 查询，连接不能及时归还。
- sidecar 重连风暴会导致 MySQL 连接池耗尽，页面出现 500 或超时。

已修复：

- SSE 循环中 ORM 对象转普通 dict 后主动 `db.session.remove()`。
- 消息轮询节流，避免每 2 秒打 DB。
- `last_activity/status` 写库降频到 60 秒。
- MySQL 连接池参数收敛，降低单服务可占用连接上限。

### 2. stale 连接清理死锁

问题：

- `_cleanup_stale_connections()` 在每次 SSE 建连时 ORM 批量更新 `openclaw_instances`。
- 多个 sidecar 并发重连时容易触发 MySQL deadlock，拖垮 heartbeat、todos、dashboard 等业务 API。

已修复：

- stale 清理增加 120 秒节流和全局锁。
- 清理逻辑改为独立 pymysql 单条 `UPDATE`。
- 异常只记录 warning，不影响当前请求。
- 补齐 `GET /api/v1/openclaws/<id>/todos/submitted`。

### 3. PowerShell/SSH 中文乱码

问题：

- 本机 PowerShell heredoc 直传远端脚本时，中文可能变成 `????`。

处理原则：

- 更新线上 DB 中文内容时优先 scp UTF-8 文件到远端，再由远端 Python 读取文件写入。
- 远端烟测脚本断言尽量使用 ASCII 或 `\uXXXX`，避免 PowerShell 管道破坏中文。

## 五、当前风险与注意事项

1. 远端 Agent 目标机 SSH/命令链路偶发卡住。最近一次调用大赫 restart sync 超过 2 分钟未返回，已重启 `openclaw-web` 清掉卡住 worker。后续需要给重启同步链路加更细的命令超时与错误返回。
2. 旧 sidecar 或旧 SSE 客户端仍可能在个别机器残留。若再次出现重复消息、待办不消费、连接池升高，优先查目标机旧进程和 `/api/openclaws/<id>/events` 连接数。
3. Hermes 额外工作目录不应放在 `/root`、`/etc`、`/usr` 等系统目录下。工程代码如果需要被 Agent 访问，应迁移到 `/opt/agent_work/<project>` 或 `/opt/agent_share/<project>`。
4. 线上验证尽量避免长时间 `create_app()+test_client` 脚本，尤其在 SSE 连接池紧张时。能用短 API 探针就用短 API 探针。
5. Skill 文档和 Hub API 必须同步更新。API 新增后，相关 `SKILL.md` 和线上 `skills.template_content` 也要同步，否则 OpenClaw 仍按旧说明执行。
