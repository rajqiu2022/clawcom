# Hub 系统功能与修改经验交接文档（2026-08-04）

本文用于交接给下一位 AI 继续维护整个 Hub 系统。它不是单一功能说明，而是近期系统功能、已上线改造、验证方式、部署经验和后续风险的总览。

## 1. 当前系统定位

Hub 是 OpenClaw / Hermes / 自定义 Agent 的统一协作平台，核心职责包括：

- 管理 Agent / OpenClaw 实例、Token、技能、模板、任务和消息。
- 管理测试生命周期：需求、测试迭代、测试计划、用例库、用例评审、测试报告、上线风险。
- 组织多 Agent 工作流：定义 runbook、派发节点、收集进度、回写结果、做门禁和人工确认。
- 提供知识库、经验记录、Skill 下发、ops verify、任务上下文、项目权限等公共能力。
- 支持匿名分享、外部临时参与、项目级隔离和 agent 侧 API 自动化。

## 6. 修改经验总表

### 6.1 后端契约

- 写后验证必须从 DB 重读 actual，不能回显请求体。
- Agent 写入 expected 要用 API canonical 字段，不要暴露 ORM 内部字段。
- 结果状态必须 fail closed，不要把未知值兜底成成功。
- 长任务 result 的幂等短路必须发生在状态和 claim 校验前。
- 同一个 `Idempotency-Key` 的 hash 要覆盖 method/path/query/body。
- 租约 owner 要同时校验 Bearer Claw 和 worker_id。

### 6.2 兼容边界

- `worker_task` 和 `agent_task` 不是同一种执行模型。
- 不要把强 claim 契约套到 `agent_task`，否则会破坏 OpenClaw/Hermes。
- 新功能如果只服务自定义 Worker，要明确隔离在 `worker_task` 分支。

### 6.3 前端 UI

- hover-only 入口不可靠，关键操作要常显。
- 弹窗内浮层要检查初始隐藏、展开方向、z-index、滚动容器和按钮可点击性。
- `[hidden]` 遇到显式 `display:flex/grid` 必须加作者级 `[hidden]` CSS。
- 内联 JS 要用 `node --check` 验证，尤其是模板中有中文、引号、onclick 属性时。

### 6.4 部署

- 不要盲目整文件覆盖线上漂移文件。
- 复杂部署脚本要在每个新增符号上做独立 idempotent patch 判断。
- smoke 需要覆盖真实 API 和 DB 回读，但临时数据必须在 `finally` 清理。
- 部署失败后要验证回滚结果，而不是只相信脚本输出。

### 6.5 测试

- 先写失败测试再改代码，尤其是契约类改动。
- API 集成测试要覆盖错误 owner、过期、重复请求、终态重放。
- 前端合同测试只检查 DOM 不够，要结合实际可发现性和视觉遮挡问题。
