# Hub 测试左移 MVP-A：开发与灰度说明

## 本期交付边界

本期采用增量接入，不替换现有 Workflow、测试报告、测试计划和用例评审流程：

- Workflow/Agent 可按精确代码与需求基线创建 `Analysis Run`。
- 分析结果写入结构化 `Finding`，同一问题可跨分析复用并保留事件审计。
- Workflow 已有的自定义 HTML 测试报告继续作为展示载体；Developer AI 通过 API 读取报告正文和 Finding，不直接修改 HTML。
- 测试迭代在功能开关开启后增加“代码分析”页签，可筛选、查看详情、添加备注并执行受约束的状态变更。
- Hub 可签发一次性邀请码；Developer AI 兑换短期 Token 后，只能访问指定报告/Analysis/Finding 和明确授权的动作。

## 兼容与安全策略

- `SHIFT_LEFT_ENABLED` 默认关闭。关闭时新 API 返回 `SHIFT_LEFT_DISABLED`，测试计划不显示“代码分析”页签。
- 数据库迁移只新增表，不修改现有业务表。
- 新能力不会自动触发 Workflow，也不会自动改变现有报告或用例评审状态。
- 所有写 API 要求 `Idempotency-Key`，Finding 状态变更还要求 `from_revision`，避免重复提交和覆盖并发修改。
- 邀请码只返回一次，服务端仅保存哈希；短期 Token 有过期时间、调用次数、scope、对象范围和撤销审计。
- Developer AI 不能新增/提升证据，不能确认自己生成的问题，执行修复的 Agent 不能自行验收关闭。

## 灰度部署顺序

1. 备份数据库并执行 `ops/migrations/20260810_shift_left_mvp_a.sql`。
2. 部署代码，但保持 `SHIFT_LEFT_ENABLED=0`。
3. 回归现有 Workflow worker、测试报告可见性、用例评审和测试计划。
4. 在灰度环境设置 `SHIFT_LEFT_ENABLED=1` 并重启 Web 服务。
5. 仅选择一个测试迭代，由 Workflow 显式提交 Analysis/Finding；确认报告和页签数据一致。
6. 验证邀请码兑换、备注、状态更新、撤销和过期行为后，再扩大使用范围。

## 回滚

- 先将 `SHIFT_LEFT_ENABLED=0` 并重启 Web 服务，新入口立即隐藏，新 API 停止服务。
- 保留新增表便于审计和后续恢复；无需回滚现有业务表或删除数据。
- 如需回退代码，新增表不会被旧版本读取，不影响原有流程。
