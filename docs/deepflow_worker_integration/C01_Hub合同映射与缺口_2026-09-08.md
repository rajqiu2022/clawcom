## W-00 Direct 事实

Windows `scripts/start.ps1` 与 Linux `LinuxCodexServiceConfig.unit()` 都只在 `codex_host_v4_canary` 启动 `codex_worker_v4_entry.py`。正式 `agent_direct` 启动 `sidecar_v2.py`，并拒绝已安装 Job Service 的不兼容组合。

因此，`codex_worker_v4/store.py::WorkerStateStore` 虽然已有 task、thread 和 outbox 持久化能力，却不是当前 Direct 生产 Store。W-02应抽取或适配其能力到 Direct 实际入口，不能直接宣称已有 Store 已覆盖生产链路。

## M1明确缺口

1. **H01_AGENT_DIRECT_ADMISSION**：现有 Step claim 接口只允许 `worker_task`。`agent_task` 没有原子容量准入或 WAITING 原因合同。
2. **H02_AGENT_DIRECT_FENCING**：result/progress 对 `worker_task` 校验 fencing，但 `agent_task` 不校验。旧 Direct attempt 的迟到写不能仅依赖幂等 key 防护。
3. **H02_RUN_RECONCILIATION**：已有 Step 心跳丢失和有限超时收敛，但缺少 Hub 与 Worker 已落盘结果之间的统一对账收据。
4. **W02_DIRECT_OPERATION_JOURNAL**：Direct 尚无 `prepared → running → result_ready → acked` 的工具 operation journal。

H-01/H-02实施时不得把 `agent_task` 改回 `worker_task`，也不得恢复 Job Service。推荐增加只约束当前 Run/Step/attempt 的 Direct execution lease，并让 Sidecar 在调用可选 Runner 前取得和持久化该凭据；一般Agent文件、Git和分析行为不受 Runner 合同约束。

## M2已识别缺口

Hub 报告附件上传当前限制单文件 10 MiB，但上传事务不保存调用方提供的 idempotency key 或内容 SHA。Worker Publisher虽然能通过报告回读恢复，却不能排除上传成功、响应丢失时的重复附件竞态。H-03应在既有上传接口补幂等唯一约束，而不是重写 Publisher。
