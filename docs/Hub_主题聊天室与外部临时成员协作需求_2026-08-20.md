# Hub 主题聊天室与外部临时成员协作需求

日期：2026-08-20  
状态：已确认，作为开发与验收基线  
适用范围：Hub Web、Hub API、Agent SSE Sidecar、Skill 文档

## 1. 背景

Hub 当前已经具备用户与 Agent、Agent 与 Agent 的点对点消息、SSE 实时推送、离线补推、消息状态回写及临时协作 Token，但缺少一个以“主题”为中心、可容纳多个人和多个 Agent 持续讨论的共享空间。

本需求在现有通信机制上增加“主题聊天室”。聊天室由 Hub 用户或已注册 Agent 创建，可邀请 Hub 注册 Agent、Hub 用户及外部临时成员加入。消息和成员身份都由 Hub 持久化，短期 Token 只负责访问授权，Token 到期或重新签发不会影响聊天室及历史消息。

## 2. 基本原则

1. 优先复用 Hub 现有身份认证、Agent SSE、消息幂等、审计和临时 Token 安全能力，不替换现有点对点通信。
2. `ClawMessage` 继续服务点对点消息；聊天室使用独立的数据模型，避免把一条群聊消息复制成多条点对点消息后产生状态漂移。
3. 聊天室、成员身份、访问 Token 三者分离：聊天室和成员长期存在，Token 可以短期失效和重新签发。
4. 普通聊天消息只落库和更新未读，不自动唤起所有 Agent。只有明确 `@Agent`、`@所有人` 或房间策略要求响应时，才投递给 Agent 执行，避免正常聊天消耗模型资源。
5. 安全门禁应保护身份、范围和防循环，但不应让正常聊天室因为单个 Agent 离线、回复失败或未读而整体阻断。
6. 所有发送方身份均由当前登录 Session、Agent Token 或临时 Token 反查，禁止请求体自报身份。

## 3. 目标与非目标

### 3.1 本期目标

- 用户或 Hub 注册 Agent 创建主题聊天室。
- 邀请 Hub 注册用户或 Agent 成为聊天室成员。
- 成员发送消息、查看历史和未读状态。
- 支持结构化 `@某个成员` 和 `@所有人`。
- 被点名的 Agent 通过现有 SSE 收到消息并可在原聊天室回复。
- 外部人员通过邀请链接申请临时成员身份和聊天室专用 Token。
- 临时 Token 默认有效 48 小时；到期后可重新申请，新 Token 继续绑定原成员身份。
- 只要聊天室和成员没有被删除或移除，聊天记录一直保留，不随 Token 过期而丢失。
- 支持撤销邀请、移除成员、禁用成员 Token 和删除聊天室。

### 3.2 本期非目标

- 不把聊天室直接当作 Workflow 调度器或任务状态机。
- 不默认把普通聊天消息转成待办、工单或企微通知。
- 不要求首期支持音视频、语音通话、屏幕共享和大型附件。
- 不修改已有点对点消息、课题讨论、用例评审和 Developer AI 协作接口的既有语义。

## 4. 核心对象

### 4.1 ChatRoom

主题聊天室主体。

建议字段：

| 字段 | 说明 |
| --- | --- |
| `id` | 聊天室 ID |
| `title` | 主题名称 |
| `description` | 主题说明，可为空 |
| `project_id` | 可选项目范围；为空表示全局房间 |
| `owner_member_id` | 房主成员 ID |
| `status` | `active/archived/deleted` |
| `history_visibility` | `all` 或 `since_join`，默认 `all` |
| `mention_all_enabled` | 是否允许 `@所有人`，默认开启 |
| `agent_response_policy` | 默认 `mention_only` |
| `max_agent_chain_depth` | Agent 自动对话链深度，默认 5，可配置 |
| `created_at/updated_at/deleted_at` | 生命周期时间 |

`archived` 为只读归档；`deleted` 对普通成员不可见并立即使访问 Token 失效。删除默认采用软删除，便于审计和误删恢复，后续可由管理员按保留策略物理清理。

### 4.2 ChatRoomMember

成员是消息作者和历史归属的稳定身份，不等于登录 Token。

| 字段 | 说明 |
| --- | --- |
| `id` | 房间内稳定成员 ID |
| `room_id` | 聊天室 ID |
| `member_type` | `user/claw/guest` |
| `user_id` | Hub 用户成员使用 |
| `claw_id` | Hub 注册 Agent 成员使用 |
| `guest_identity_id` | 外部成员使用 |
| `display_name` | 房间内显示名 |
| `role` | `owner/moderator/member` |
| `status` | `active/removed/left/banned` |
| `joined_at/left_at` | 加入和退出时间 |
| `last_read_message_id` | 未读游标 |

同一个 Hub 用户或 Agent 在同一个聊天室只能有一个活动成员。外部成员显示“外部”徽标，不能伪装成 Hub 注册用户或 Agent。

### 4.3 ChatRoomMessage

聊天室中的唯一消息记录。

| 字段 | 说明 |
| --- | --- |
| `id` | 全局消息 ID |
| `room_id` | 聊天室 ID |
| `sender_member_id` | 真实发送成员 |
| `content` | 文本或 Markdown 内容 |
| `content_format` | 首期支持 `text/markdown` |
| `reply_to_message_id` | 可选回复消息 |
| `client_message_id` | 客户端幂等 ID |
| `agent_chain_depth` | Agent 自动对话链深度 |
| `status` | `active/deleted` |
| `created_at/deleted_at` | 时间 |

消息发送成功后即视为聊天室历史的一部分。逐成员送达、已读和 Agent 处理状态不写在消息主记录上。

### 4.4 ChatRoomMention 与 ChatRoomDelivery

`ChatRoomMention` 保存结构化提及：

- `mention_type=member` + `target_member_id`：`@某个人`；
- `mention_type=all`：`@所有人`。

前端选择成员时写入稳定 `member_id`，后端不依赖纯文本名称解析，避免重名和改名造成误投递。消息正文可以显示 `@名称`，但路由以结构化 mentions 为准。

`ChatRoomDelivery` 按接收成员保存 `unread/delivered/read/processing/done/failed/skipped`，其中：

- 用户和外部成员通常只使用未读、送达、已读；
- Agent 被明确提及时进入现有处理闭环；
- 某个 Agent 失败只更新自己的 Delivery，不把聊天室消息整体标为失败。

### 4.5 ChatRoomInvite、GuestIdentity 与 GuestSession

外部邀请和临时身份采用三层结构：

1. `ChatRoomInvite`：房间级邀请链接，保存邀请码哈希、有效状态、可选截止时间、最大加入人数和创建者，可撤销或轮换。
2. `GuestIdentity`：外部人员在房间内的稳定身份，保存显示名、状态和不可逆的恢复凭据哈希。
3. `GuestSession`：短期访问会话，Token 只保存哈希，绑定 `room_id + member_id`，默认 48 小时有效。

这样 Token 到期后只新增或替换 `GuestSession`，不创建新的聊天室和消息作者，历史记录仍绑定同一个 `ChatRoomMember`。

## 5. 权限模型

| 操作 | 房主 | 管理员/主持人 | 普通成员 | 外部成员 |
| --- | --- | --- | --- | --- |
| 查看房间和历史 | 是 | 是 | 是 | 是，受历史可见策略限制 |
| 发送消息和 `@成员` | 是 | 是 | 是 | 是 |
| `@所有人` | 是 | 是 | 默认允许，可由房间策略关闭 | 默认允许，可由房间策略关闭 |
| 邀请 Hub 用户/Agent | 是 | 是 | 否 | 否 |
| 创建/撤销外部邀请链接 | 是 | 是 | 否 | 否 |
| 移除或封禁成员 | 是 | 是，但不能移除房主 | 否 | 否 |
| 归档/删除聊天室 | 是 | Hub 超级管理员可操作 | 否 | 否 |

项目聊天室只能邀请有该项目访问权的 Hub 用户和 Agent。全局聊天室由 Hub 管理员或具备全局通信权限的 Agent 创建。普通项目 Agent 不应借聊天室跨项目枚举成员。

## 6. 主要用户流程

### 6.1 用户创建并邀请 Agent

1. 用户填写主题、说明和项目范围，创建聊天室并成为房主。
2. 用户从 Hub 注册 Agent 列表中选择成员。
3. Hub 创建成员关系，并通过现有 SSE 向 Agent 推送 `room_invited`。
4. Agent 可以读取房间概要和历史，但不会因为加入房间就自动调用模型。
5. 用户发送普通消息时只保存历史；用户 `@小牛` 时，Hub 才向小牛投递 `room_message`。

### 6.2 Agent 创建聊天室

1. 已注册 Agent 使用自身 Bearer Token 创建项目范围内的聊天室。
2. Hub 从 Token 绑定创建者身份，不接受请求体伪造 `creator_claw_id`。
3. Agent 邀请其可见范围内的 Agent 或 Hub 用户。
4. Agent 在聊天室发言、提及其他成员或回复指定消息。

### 6.3 `@某个人`

1. 客户端从成员列表选择目标成员并发送结构化 mention。
2. Hub 保存一条消息和目标成员的 Delivery。
3. 目标为 Hub 用户或外部成员时，更新未读并实时推送给在线浏览器。
4. 目标为 Agent 时，通过现有 SSE 发送 `room_message` 事件。
5. Sidecar 只处理一次该 `message_id + target_member_id`，读取必要上下文后在原房间回复。

### 6.4 `@所有人`

1. Hub 展开当前所有活动成员，但消息主记录仍只有一条。
2. 为每个成员创建 Delivery；在线成员实时收到，离线成员下次上线补推未读。
3. 房间内 Agent 均可收到处理事件。
4. 同一条消息同时包含 `@成员` 和 `@所有人` 时，目标集合去重，每个成员只生成一条 Delivery。
5. `@所有人` 受房间开关、频率限制和幂等控制；限频只拒绝当前发送，不影响房间其他消息。

### 6.5 外部人员首次加入

1. 房主生成外部邀请链接，例如 `/chat/join#invite=room_ci_xxx`。
2. 外部人员打开链接，填写显示名并确认加入。
3. Hub 校验邀请仍有效、聊天室未删除、名额未耗尽。
4. Hub 创建 `GuestIdentity + ChatRoomMember`，签发默认 48 小时的房间专用 Token。
5. 首次响应同时返回一次性的 `resume_secret`，浏览器安全保存；Hub 只保存哈希。
6. 外部成员进入聊天室并按房间历史可见策略读取消息。

外部 Token 只允许访问指定聊天室的概要、成员、消息、发送、已读和续签接口，不能访问 Hub 其他项目、用例、报告、Agent 列表或管理接口。

### 6.6 外部 Token 到期后重新申请

1. 外部成员重新打开原邀请链接或进入续签页。
2. 客户端提交邀请参数和 `resume_secret`；显示名不能作为身份恢复凭据。
3. Hub 确认聊天室仍有效、成员未被移除或封禁。
4. Hub 签发新的短期 Token，继续绑定原 `member_id`。
5. 原消息、未读游标和成员显示身份保持不变。

如果用户丢失 `resume_secret`，可通过仍有效的邀请链接以新外部成员身份加入；旧身份和历史消息保留，但不能仅凭相同显示名接管旧身份。

撤销邀请链接只阻止新成员加入。已加入外部成员能否续签由其成员状态决定；如需彻底禁止，应移除或封禁该成员，Hub 随即使其所有 Token 失效。

## 7. Agent 消息处理规则

### 7.1 SSE 事件

复用 Agent 现有 SSE 连接，新增事件：

- `room_invited`：被加入聊天室；
- `room_message`：被直接提及、被 `@所有人` 提及或房间策略要求处理；
- `room_member_changed`：成员被移除、房间归档或删除等必要状态变更。

不为聊天室建立第二条 SSE 连接。

### 7.2 Agent 上下文

`room_message` 事件只携带可信最小上下文：

- `room_id/title`；
- 当前 `message_id`、发送者及正文；
- mentions、`reply_to_message_id`；
- 最近少量消息摘要或 `context_url`；
- Agent 自己的 `member_id`、Delivery ID 和幂等键；
- `agent_chain_depth` 和响应策略。

Sidecar 需要更多历史时按游标调用上下文 API，不把整个聊天室历史一次性注入模型。

### 7.3 防重复与防循环

- Hub 按 `room_id + sender_member_id + client_message_id` 保证发送幂等。
- Sidecar 按 `delivery_id` 保证同一目标只触发一次模型处理。
- Agent 普通回复不自动附带 mention；只有明确需要继续对话或委派时才再次 `@成员`。
- Agent 触发的 Agent 链超过 `max_agent_chain_depth` 后，消息仍正常落库，但自动投递标记为 `skipped`，提示需要人工继续；不阻断用户聊天。
- `@所有人` 设置短时间冷却和单房间限频，默认值可配置，不写死到协议。

## 8. API 草案

### 8.1 房间与成员

```text
POST   /api/v1/chat-rooms
GET    /api/v1/chat-rooms
GET    /api/v1/chat-rooms/{room_id}
PATCH  /api/v1/chat-rooms/{room_id}
DELETE /api/v1/chat-rooms/{room_id}

GET    /api/v1/chat-rooms/{room_id}/members
POST   /api/v1/chat-rooms/{room_id}/members
DELETE /api/v1/chat-rooms/{room_id}/members/{member_id}
```

创建房间示例：

```json
{
  "title": "RacingGO 登录稳定性讨论",
  "description": "集中讨论登录链路问题、证据和修复进度",
  "project_id": 1,
  "history_visibility": "all",
  "agent_response_policy": "mention_only"
}
```

邀请 Hub Agent 示例：

```json
{
  "members": [
    {"member_type": "claw", "claw_id": 11},
    {"member_type": "claw", "claw_id": 32}
  ]
}
```

### 8.2 消息与已读

```text
GET  /api/v1/chat-rooms/{room_id}/messages?after_id=&before_id=&page_size=
POST /api/v1/chat-rooms/{room_id}/messages
POST /api/v1/chat-rooms/{room_id}/read
GET  /api/v1/chat-rooms/{room_id}/unread
```

发送消息示例：

```json
{
  "content": "@小牛 请核对最新 Run 的失败原因，@所有人 补充遗漏证据。",
  "content_format": "markdown",
  "reply_to_message_id": 120,
  "client_message_id": "01J6ROOMMSG8F3...",
  "mentions": [
    {"mention_type": "member", "target_member_id": 18},
    {"mention_type": "all"}
  ]
}
```

写接口必须携带 `Idempotency-Key`。Hub 校验正文中的展示名称与结构化 mention 不冲突，但最终路由只依据结构化字段。

### 8.3 外部邀请与临时 Token

```text
POST   /api/v1/chat-rooms/{room_id}/invites
GET    /api/v1/chat-rooms/{room_id}/invites
POST   /api/v1/chat-rooms/{room_id}/invites/{invite_id}/revoke
POST   /api/v1/chat-room-invites/exchange
POST   /api/v1/chat-room-sessions/renew
POST   /api/v1/chat-room-sessions/revoke
```

首次申请示例：

```json
{
  "invitation_code": "room_ci_xxx",
  "display_name": "外部研发-张三",
  "token_ttl_minutes": 2880
}
```

续签示例：

```json
{
  "room_id": 15,
  "member_id": 27,
  "resume_secret": "room_rs_xxx",
  "token_ttl_minutes": 2880
}
```

默认 Token 有效期为 2880 分钟（48 小时）。允许范围由系统配置控制，首期建议 1 小时至 7 天；房主可以选有效期，但不能发放永久 Token。

## 9. Web 页面

### 9.1 Hub 内部页面

- 在现有通信中心页面的顶层页签中，新增独立的“聊天室”页签，与“任务下发 / 聊天 / 消息记录 / 状态监控”并列。
- 现有“聊天”页签继续承载 Web/Admin 与单个 Agent 的点对点聊天；“聊天室”页签承载本需求的多成员主题聊天室，二者不能合并或互相替换。
- “聊天室”页签显示未读总数徽标；存在新消息时，无论用户当前在哪个通信中心页签，都应更新徽标。
- 支持 `/hub?view=rooms&room_id={room_id}` 形式的直达链接。刷新页面或从通知进入时，自动打开聊天室页签和指定房间。

聊天室页签采用三栏布局：

1. **左侧房间列表**
   - 显示用户当前有权访问的聊天室；
   - 展示房间名称、最后一条消息摘要、最后更新时间、未读数和归档状态；
   - 支持按最近活跃排序、仅看未读和按名称搜索；
   - 提供“新建聊天室”按钮；没有房间时展示创建引导，而不是空白页面。
2. **中间聊天内容区**
   - 顶部显示主题、说明、项目范围、成员数和房间状态；
   - 显示真实聊天室历史，包括用户、Agent 和外部成员发送的内容；
   - 消息展示发送者类型徽标、时间、正文、回复关系、`@成员/@所有人` 和发送/处理状态；
   - 历史消息按游标向上加载，进入房间默认定位到第一条未读消息；没有未读时定位到最新消息；
   - 输入区支持 Markdown、成员选择器、`@所有人`、回复指定消息和发送状态；
   - 切换房间时保留各房间草稿，不把未发送内容带到另一个房间。
3. **右侧成员与管理区**
   - 显示房主、主持人、普通成员、外部成员和 Agent 在线/能力状态；
   - 房主或主持人可邀请 Hub 用户/Agent、生成或撤销外部邀请链接、移除成员；
   - 展示外部成员 Token 到期和最后活动时间，但不展示 Token 明文；
   - 房主可修改主题和策略、归档或删除聊天室。

页面至少具备加载中、无权限、房间已删除、网络失败和重试状态。某个 Agent 处理失败时，在对应消息的该 Agent Delivery 上展示失败提示，不应让整条消息或页面显示为发送失败。

### 9.2 外部加入页面

- 不要求 Hub 登录。
- 邀请码保存在 URL fragment，避免被服务器访问日志、Referer 或聊天预览提前消费。
- 首次进入填写显示名并确认申请临时身份。
- Token 到期时显示“重新申请访问”，优先使用本地 `resume_secret` 恢复原成员。
- 页面只展示当前聊天室，不出现 Hub 全局导航和其他资源入口。

浏览器实时消息优先复用现有 Socket.IO；不可用时回退短轮询。Agent 仍使用现有 SSE。

## 10. 安全与审计

- 邀请码、访问 Token、`resume_secret` 明文只在必要响应中返回，Hub 只保存哈希。
- 临时 Token 必须绑定 `room_id + member_id + scopes + expires_at`。
- 房间删除、成员移除/封禁后，对应 Token 立即失效，不等待 TTL。
- 房主可查看外部会话的签发、续签、最后活动和撤销时间，但不能查看 Token 明文。
- 审计记录至少覆盖：创建/删除房间、邀请/移除成员、生成/撤销邀请、首次兑换、Token 续签、成员封禁和 `@所有人`。
- 消息正文按 Markdown 安全渲染，禁止脚本、事件属性和未经许可的内嵌 HTML。
- 对发送、加入和 Token 续签做按房间/身份/IP 的温和限频；达到限制只拒绝当前请求，不锁死聊天室。
- Hub 用户、注册 Agent 和外部成员使用不同的视觉标识与 `member_type`，不能通过改显示名冒充。

## 11. 与现有系统的兼容关系

| 现有能力 | 处理方式 |
| --- | --- |
| `ClawMessage` 点对点消息 | 保持不变；聊天室不复用其单接收方主表 |
| Agent SSE | 复用连接，新增 room 事件类型 |
| Sidecar 消息处理 | 增加 room handler，不改变现有 `message` handler |
| 临时 Developer AI 协作 | 复用哈希、TTL、幂等和审计服务；不改变一次性用例评审邀请语义 |
| Topic/课题讨论 | 保持长文讨论和评审定位；聊天室用于实时多方交流 |
| Workflow/待办 | 默认不自动转换；后续可通过显式动作从消息创建任务 |
| 企微通知 | 默认不逐条外发；后续按房间策略通知房主或被点名用户 |

## 12. Hub 与 Worker 分工

### 12.1 Hub

- 房间、成员、消息、mention、Delivery、邀请和临时会话持久化。
- 权限校验、发送者身份绑定、`@` 展开、幂等、限频和审计。
- 向目标 Agent 的现有 SSE 连接发送可信 room 事件。
- 提供 Web 实时消息、历史分页、未读数和外部加入页面。
- Token 签发、续签、撤销及房间/成员状态联动失效。

### 12.2 Agent Sidecar / Worker

- 识别 `room_invited`、`room_message` 和必要状态事件。
- 仅在明确提及或房间策略要求时调用模型。
- 按 `delivery_id` 去重，回写 processing/done/failed。
- 使用房间专用 API 获取有限上下文并在原房间回复。
- 不自行解析纯文本 `@名字` 决定接收人，不把 Agent 思考过程发入聊天室。
- 保留当前点对点消息、企微聊天和 Workflow 执行逻辑。

## 13. 数据迁移与发布策略

1. 新表和新接口全部增量增加，不迁移或重写历史 `claw_messages`。
2. 使用 `CHAT_ROOM_ENABLED` 功能开关，默认关闭入口；数据库迁移和代码上线后再灰度开启。
3. 先验证用户 + 单 Agent 房间，再验证多 Agent 与 `@所有人`，最后开放外部邀请。
4. Sidecar 未升级时仍可作为房间成员并查看历史，但 Hub 标记其 `room_event_capable=false`，被 `@` 时明确显示“当前 Agent 版本不支持聊天室事件”，不影响其他成员。
5. 首期新增独立 `chat-room` Skill；能力稳定后再在 `manager-hub` 中增加入口说明，避免旧 Agent 因文档更新误用未支持接口。

## 14. 验收标准

### 14.1 核心功能

- 通信中心出现独立“聊天室”页签，原“聊天”页签及点对点聊天功能保持不变。
- 进入聊天室页签能看到有权访问的房间列表；选择房间能看到真实聊天内容、成员、回复关系和历史消息。
- 聊天室未读徽标、房间未读数和进入后的已读游标保持一致；刷新页面不丢失。
- 通过带 `room_id` 的直达链接能打开指定聊天室；无权限或房间已删除时显示明确状态，不泄露房间内容。
- 长聊天记录按游标加载，进入房间定位第一条未读消息，不一次性渲染全部历史。
- 用户和注册 Agent 均能创建聊天室，创建者自动成为房主。
- 房主能邀请 Hub 注册 Agent，在线 Agent 实时收到邀请，离线后可补取。
- 普通消息不会触发未被提及 Agent 的模型调用。
- `@某个 Agent` 只投递给指定 Agent；其他成员能看到消息但不会被自动唤起。
- `@所有人` 为所有活动成员建立 Delivery，所有兼容 Agent 各处理一次。
- Agent 回复落在同一聊天室，发送者身份不可伪造。
- 同一 `Idempotency-Key/client_message_id` 重放不产生重复消息或重复模型调用。

### 14.2 外部成员

- 未注册 Hub 的外部人员可通过有效邀请链接申请成员身份和默认 48 小时 Token。
- 临时 Token 只能访问指定聊天室，访问其他 Hub API 返回范围拒绝。
- Token 过期后，使用 `resume_secret` 能获得新 Token，并保持相同 `member_id`、历史消息和未读状态。
- 丢失恢复凭据时不能凭相同显示名接管旧身份。
- 撤销邀请后不能新增外部成员；移除成员后其所有 Token 立即失效。
- 聊天室未删除时历史消息不因邀请过期、Token 过期、成员离线或重新签发而丢失。
- 聊天室删除后普通成员不可继续访问，所有临时 Token 失效。

### 14.3 稳定性与兼容性

- 新功能关闭时，现有通信中心、点对点消息、Workflow、企微和用例评审行为不变。
- 一个 Agent 处理失败只影响自己的 Delivery，不改变消息对其他成员的可见性。
- SSE 重连不会导致同一聊天室消息重复调用模型。
- 长聊天室通过游标分页读取，Sidecar 不一次性注入全部历史。
- `@所有人` 或 Agent 相互提及时不存在无限自动回复循环。

## 16. 建议默认值（实现时保持可配置）

以下参数是为了让首版可以直接开发和联调的建议值，不作为不可调整的硬规则：

| 参数 | 建议值 |
| --- | --- |
| 外部访问 Token | 默认 48 小时，建议允许 1 小时至 7 天 |
| 邀请链接 | 默认持续有效，直到撤销、轮换或聊天室删除；可选截止时间和人数上限 |
| 历史可见范围 | 默认允许新成员查看全部历史，可切换为加入后可见 |
| Agent 响应策略 | 默认只响应明确提及，不响应普通房间消息 |
| Agent 自动对话深度 | 默认 5 层，超过后只保存消息并停止自动投递 |
| `@所有人` | 默认开启并限频，房主可关闭 |
