# 用例设计维度检查清单

> 每次生成用例前，逐条对照以下 9 个维度，确保覆盖面足够。
> 本清单来源于 RacingGO 推关逻辑用例设计实战经验（2026-04-09）。

---

## 维度一：正向基础路径

最基础的冒烟用例，验证核心功能是否可用。

- [ ] 主流程走通（Happy Path）
- [ ] 初始状态正确（如首次进入、初始值为1）
- [ ] 结果展示正确（弹窗、数值、界面反馈）
- [ ] 数据与 UI 一致（界面显示值 == 后端实际值）

---

## 维度二：逆向路径（失败分支）

功能"不该发生的"是否被正确拦截。

- [ ] 失败/取消不触发成功逻辑（如游戏失败不推关）
- [ ] 操作取消不留副作用
- [ ] 错误状态有兜底展示（弹窗/提示，不是白屏）
- [ ] 逆向操作后数据与正向前保持一致

---

## 维度三：边界值

数值/状态边界最容易出 Bug。

- [ ] 最小值（初始值、第1条记录）
- [ ] 最大值（最后一关、上限数量、最大字符数）
- [ ] 临界状态切换（刚好通关 vs 差一步通关）
- [ ] 首次 vs 重复（首次启动 vs 重复启动行为是否一致）

---

## 维度四：异常与容错

用户在不寻常条件下使用，系统是否能正确处理。

- [ ] **强退/崩溃**：局内/流程中强杀进程，重启后状态正确
- [ ] **弹窗未确认时强退**：数据写入时机是否正确（事件触发时写入 vs 用户确认后写入）
- [ ] **网络断开**：操作中断网，恢复后数据是否补传/一致
- [ ] **弱网超时**：接口超时后本地与服务端是否最终一致
- [ ] **离线模式**：离线操作后的行为是否符合产品规格

---

## 维度五：多设备 & 账号场景

移动端/游戏特有的高频场景，极易产生数据一致性问题。

- [ ] **顶号登录**：被踢下线后重新登录，进度/数据以服务端为准
- [ ] **顶号发生在关键流程中**（如局内、支付中）：该流程不计完成，不产生脏数据
- [ ] **多设备同账号**：旧设备本地进度不覆盖服务端最高进度
- [ ] **卸载重装**：行为是否符合产品规格（新用户 or 保留数据）
- [ ] **重复启动**：同设备重复打开，不重置数据

---

## 维度六：数据一致性 & 持久化

数据在各层之间流转是否正确，不丢、不重、不错写。

- [ ] 本地 vs 服务端一致（操作后两端数据吻合）
- [ ] **写入时机明确**：操作触发时写入 还是 用户确认后写入？行为需一致且符合规格
- [ ] 失败/中断不写入成功数据
- [ ] 重启持久化：重启后进度与退出前一致

---

## 维度七：进度优先级 & 重玩逻辑

有历史进度的情况下，再次操作低级别内容是否影响最高进度。

- [ ] **重玩低关卡/历史内容通关不覆盖最高进度**
- [ ] 主入口始终展示最高未完成进度
- [ ] 低关卡结算数据只记录该关完成，不推进整体最高进度
- [ ] 已完成内容重玩产生的数据写入逻辑正确

---

## 维度八：防重复操作 & 竞态

用户快速操作或并发请求导致数据被重复写入。

- [ ] **快速连点按钮**：不重复弹出/进入/写入
- [ ] **快速连点确认**：数据只变化一次，不累加
- [ ] 服务端接口重试时幂等处理（接口被调用多次结果一致）

---

## 维度九：UI 与数据同步

界面展示的数值是否与实际数据逻辑吻合。

- [ ] 弹窗编号/数值 vs 主界面编号/数值的对应关系正确
- [ ] 状态刷新时机（返回主界面后 UI 立即刷新还是延迟？）
- [ ] 异常状态 UI 有明确提示（不是空白、不是卡住）
- [ ] 结算/完成弹窗展示的数据 = 实际发生的数据

---

## 快速记忆口诀

```
正向走一遍，逆向走失败
边界找极值，异常搞强退
顶号多设备，数据对一致
重玩不覆盖，连点防重复
弱网要兜底，离线看规格
```

## 典型遗漏场景速查表

| 遗漏类型 | 具体场景示例 |
|---------|------------|
| 强退场景 | 局内强退、弹窗未点确认时强退、支付中强退 |
| 顶号场景 | 主界面顶号、局内顶号、支付中顶号 |
| 重玩低进度 | 重玩低关卡通关是否影响最高进度 |
| 数据写入时机 | 通关事件触发时 vs 点击返回后写入 |
| 多设备同步 | 旧设备本地数据覆盖服务端最高进度 |
| 快速连点 | 连点关卡按钮、连点确认按钮 |
| 离线模式规格 | 离线进度是否同步、是否符合产品规格 |
| 最大值溢出 | 最后一关通关后是否溢出/崩溃 |
| 卸载重装 | 游客账号重装是否视为新用户 |
